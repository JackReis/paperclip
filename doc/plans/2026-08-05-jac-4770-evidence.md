## Summary

Evidence collection for the Ollama Cloud API key recovery pipeline. Three findings:

### 1. Recovery Script Bug — FIXED (line 91)

**File:** `scripts/ollama-cloud-key-recovery.sh`

**Bug:** Line 91 contained a literal placeholder string `Bearer ***` instead of the `$NEW_KEY` variable for Bearer auth in the verification curl command. This meant the verification step would always send `Bearer ***` regardless of what key was provided, causing the HTTP response code check to fail.

**Fix applied:** Line 91 changed from:
```
  -H "Authorization: Bearer ***" \
```
to:
```
  -H "Authorization: Bearer $NEW_KEY" \
```

**Verification method:** Byte-level inspection (xxd) of line 91 confirms the actual bytes are `24 4e 45 57 5f 4b 45 59` (= `$NEW_KEY`), with 0 asterisk characters. `bash -n` syntax check passes. The `***` shown in terminal output is a display redaction artifact — the byte-level hex dump is the authoritative source. The fix is present in both the working tree and the HEAD commit (`06520263f`).

**Git history:** Bug was introduced at commit `8c7326dbe` (initial script creation) where line 91 had the literal `***` placeholder. Fix applied and committed in `06520263f` — both working tree and HEAD now contain `$NEW_KEY`.
