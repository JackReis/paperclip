## Thinking Path

> - Paperclip is the open source app people use to manage AI agents for work
> - Several subsystems were involved: agent identity folders (organize fleets into a hierarchy), cost-event identity and idempotency (deduplicate re-ingested run events), and the migration/tooling layer that keeps them typecheck-clean
> - Two small upstream regressions blocked the work: a missing type declaration in `acpx-engine`, a stale path in the root `tsconfig.json`, and a barrel re-export that pulled `node:crypto` into browser-context plugin typechecks
> - The schema migration numbers also collided with later migrations that had already landed on master, so the new migrations needed renumbering to free slots
> - This pull request collects the agent-folders feature, the event-identity/idempotency enforcement, related route/service/shared types, plus the typecheck and numbering fixes needed for all of it to land together
> - The benefit is a working, typecheck-clean integration of an agent hierarchy feature plus idempotent AI-run cost accounting, ready for upstream review

## Linked Issues or Issue Description

**(B) No public issue exists — describing the problem following the feature template:**

**What problem are you trying to solve?**
Fleet agents need to be organized into a folder hierarchy so large fleets can partition capabilities and visibility. Cost-event ingestion needs deterministic identity and idempotency so replayed runs do not produce duplicate records. Two latent typecheck bugs block any branch that attempts to integrate these features cleanly.

**Describe the solution you'd like**
1. A new `agent_folders` table with folder hierarchy, routes, services, shared types, and adapter wiring. Plus a `folder_id` column on `agents`.
2. Event identity columns on `cost_events` and `run_events` (`ingest_id`, `payload_hash`, `source_event_id`, `source_system`, `event_kind`, `attempt_index`) with deterministic derivations and `ON CONFLICT DO NOTHING` upserts.
3. Typecheck fixes so the whole monorepo passes: extend `PaperclipAcpRuntimeOptions`, drop the stale `droid-local` tsconfig reference, move the event-identity re-export out of the shared barrel (it uses `node:crypto`) so browser-context plugins still typecheck, and renumber the new migrations to avoid collisions with the current master sequence.

**Describe alternatives you've considered**
Split the work into separate PRs. We tried this: the migration numbering, barrel re-export issue, and `acpx-engine` typing all interact when the branches land in sequence. One umbrella branch that integrates them was faster and safer during active development. Upstream can split on review if it prefers a smaller diff.

**Additional context**
The migrations in this PR are new (0216, 0217, 0218). The folder hierarchy feature includes its plan doc, adapter wiring (Hermes folder-instructions), service routes, and a dedicated integration test suite (JAC-4755 landed later on top of the original merge).

## Risks

- **Migration safety:** three new migrations (0216, 0217, 0218). The event-identity migration (0216) adds `NOT NULL` columns to `cost_events` and `run_events`. It includes a `DEFAULT ''` on the new columns first, then drops the default; operators with very large tables should run this migration during a quiet window. No data is destroyed.
- **Breaking change to the shared barrel:** the event-identity helpers are no longer re-exported from `@paperclipai/shared`. Server code imports them from the deep path `@paperclipai/shared/utils/event-identity`. Any downstream code that imported via the barrel will fail to typecheck; the deep import path is the public escape hatch going forward, since the barrel is also consumed by browser-context plugins.
- **Schema drift against long-lived local PostgreSQL instances:** embedded PGlite instances will apply the three migrations in order on next start. Operators with existing data should back up first.
- **Upstream drift**: fork/master (the PR base) has moved 26 commits since the rebase base. A follow-up rebase against current `origin/master` may be necessary before this can merge.
